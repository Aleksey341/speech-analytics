# 🚀 Развертывание на Amvera Cloud

## Подготовка проекта

### 1. Файлы для деплоя
Убедитесь, что у вас есть все необходимые файлы:
- `speech_analytics_server.py` - основной сервер Flask
- `requirements.txt` - зависимости Python
- `Procfile` - команда запуска для Amvera
- `runtime.txt` - версия Python
- `.env` - переменные окружения
- `index.html` - веб-интерфейс (переименуйте из "Речевая аналитика.html")

### 2. Структура проекта для Amvera
```
speech-analytics/
├── speech_analytics_server.py   # Основной сервер
├── index.html                   # Веб-интерфейс
├── requirements.txt             # Зависимости
├── Procfile                     # Команда запуска
├── runtime.txt                  # Версия Python
├── .env                         # Переменные окружения
└── .gitignore                   # Игнорируемые файлы
```

## Пошаговое развертывание

### Шаг 1: Подготовка Git репозитория
```bash
cd "C:\Users\cobra\Desktop\Речевая Аналитика"
git init
git add .
git commit -m "Initial commit: Speech Analytics System"
```

### Шаг 2: Создание проекта на Amvera
1. Перейдите на https://cloud.amvera.ru/projects
2. Нажмите "Создать проект"
3. Выберите "Из Git репозитория"
4. Подключите ваш GitHub/GitLab репозиторий

### Шаг 3: Настройка проекта
В настройках проекта на Amvera укажите:
- **Язык**: Python
- **Версия**: Python 3.9
- **Команда запуска**: `gunicorn speech_analytics_server:app --bind 0.0.0.0:$PORT`
- **Порт**: $PORT (автоматически)

### Шаг 4: Переменные окружения
В разделе "Переменные окружения" добавьте:
```
FLASK_ENV=production
SECRET_KEY=your-secret-key
DEFAULT_LANGUAGE=ru-RU
```

### Шаг 5: Деплой
1. Нажмите "Развернуть"
2. Дождитесь завершения сборки
3. Проверьте логи деплоя

## Особенности Amvera

### Ограничения
- Память: до 512MB на бесплатном тарифе
- CPU: ограничено
- Время выполнения запроса: до 30 секунд
- Размер файлов: до 50MB

### Оптимизация для Amvera
1. **Уменьшение зависимостей**:
   - Убрать PyAudio (проблемы с компиляцией)
   - Использовать легкие библиотеки

2. **Кеширование**:
   - Кешировать результаты анализа
   - Использовать Redis (если доступен)

3. **Асинхронность**:
   - Обработка больших файлов в фоне
   - Очереди задач

## Troubleshooting

### Частые проблемы:
1. **Превышение лимита памяти**: Уменьшить зависимости
2. **Таймаут запросов**: Оптимизировать алгоритмы
3. **Ошибки импорта**: Проверить requirements.txt

### Решения:
1. Использовать статические файлы для фронтенда
2. Кешировать тяжелые операции
3. Разделить на микросервисы
